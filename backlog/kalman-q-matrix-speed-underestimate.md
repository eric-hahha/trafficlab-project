# Kalman 速度低估：Q 矩陣的對角形式

**狀態：待調參**（量測日期 2026-09-07）
**成因已確認為 `KalmanTrackSmoother` 的 Q 矩陣參數，不是來源影片的重複幀。**
本文推翻 `README.md`「已知但尚未建檔」裡把速度低估歸因於 8.5 fps 重複幀的推測。
**未決事項：** `q_accel` 要調到多少定案、是否改用標準 CV 形式、`q_pos` 是否還有用途

相關程式：`trafficlab/motion/kinematics.py` 的 `KalmanTrackSmoother.update()`

---

## 結論

現行 Q 用純對角形式、位置項固定 `q_pos`：

```python
q_vel = self.q_accel * dt ** 2
Q = np.diag([self.q_pos, self.q_pos, q_vel, q_vel])
```

搭配預設值 `q_accel = 2.0`，25 fps 下速度只報出真值的 **49%**，且 150 幀內不收斂。
低估比值與真實速度無關（18 / 36 / 72 km/h 都是 0.385），確認是濾波器結構問題。

**這是調參可解的**：`q_accel` 從 `2.0` 調到 `20000`（一萬倍）後，8.5–30 fps 範圍內
誤差進入 ±1 km/h。實務素材都在 30 fps 以下，所以**不需要改結構就能修**。

代價是失去原本改成對角形式想達成的性質：調好的 `q_accel` **不能跨幀率**，
60 fps 掉到 23.07、120 fps 掉到 4.29。標準 CV 形式則全範圍正確。

## 為什麼會低估

兩個原因疊加：

1. **沒有位置–速度交叉項。** CV 模型靠 Q 的 `dt²/2` 交叉項把位置的觀測誤差回饋到
   速度狀態。純對角把這條路切斷，速度只能靠自己的 `q_vel` 慢慢長。
2. **`q_vel` 比位置項小四個量級。** 25 fps 下 `2.0 × 0.04² = 0.0032`，位置項是 `25.0`，
   相差 7812 倍。濾波器因此認定「位置可以亂跳、速度幾乎不變」，把實際位移全部
   歸給位置雜訊而不是速度。

把 `q_accel` 拉大是在補償第 2 點；第 1 點依然存在，這是調好的參數無法跨幀率的原因。

---

## 註記：原本的推論錯在哪

`kinematics.py` 現行註解與 commit `d661a11` 的 message 寫：

> at high frame rates dt⁴ collapses to ~0, the Kalman gain follows it down, and the
> filter freezes on its own prediction. A fixed q_pos keeps the gain usable at any
> frame rate.

實測相反：標準 CV（`dt³/3`）與標準 DWPA（`dt⁴/4`）在 8.5–120 fps **全範圍都正確**，
而「固定 `q_pos`」才是隨 fps 崩壞的那一個。這段理由留在程式裡會把後續調參的人
帶往錯方向，定案時應一併改掉。

`README.md`「已知但尚未建檔」裡「重複幀可能是 Kalman 速度低估 4 倍的主因之一」
同樣不成立 —— 本文的合成軌跡沒有任何重複幀，低估照樣出現。重複幀是獨立的問題
（會讓逐幀速度出現離群值），但不是低估的成因。

## 要做的話怎麼做

兩條路，選一條：

- **只調參**（範圍內夠用）：`q_accel` 預設改為 `20000` 量級，並在 config 註明
  「僅在 ≤30 fps 驗證過」。改動最小，不動結構。
- **改回標準 CV 形式**：`Q = q * [[dt³/3, 0, dt²/2, 0], [0, dt³/3, 0, dt²/2],
  [dt²/2, 0, dt, 0], [0, dt²/2, 0, dt]]`，`q ≈ 200`。`q_pos` 參數失去用途應移除。
  全幀率正確，代價是要重調一次並重跑既有輸出比對。

兩條都需要在真實素材上重跑 Hsinchu1 確認，合成軌跡只證明濾波器本身的行為。

## 什麼條件下該回來重做

- 素材出現 60 fps 以上的來源（現行對角形式會失效）
- 需要用逐幀速度而非平均速度下結論時（平均速度由路徑長÷時間算，不經 Kalman，
  不受本問題影響）
- 重複幀處理上線、`dt` 改成跳過重複幀之後（有效 fps 改變，參數要重驗）

## 重現方式

```bash
source /opt/anaconda3/bin/activate trafficlab
python3 - <<'PY'
from trafficlab.motion.kinematics import KalmanTrackSmoother
PX_PER_M, FPS = 10.0, 25.0
dt = 1.0 / FPS
cfg = {'kalman': {'r_pos': 25.0, 'q_pos': 25.0, 'q_accel': 2.0, 'init_vel_var': 100.0},
       'heading_min_speed_for_update': 0.1}
for true_kmh in (18.0, 36.0, 72.0):
    mps = true_kmh / 3.6
    ks = KalmanTrackSmoother(cfg); x = 100.0; out = []
    for i in range(100):
        out.append(ks.update([x, 100.0], dt, PX_PER_M)['speed_kmh'])
        x += mps * PX_PER_M * dt
    print(f"真值 {true_kmh:5.1f} -> 第100幀 {out[99]:6.2f}  比值 {out[99]/true_kmh:.3f}")
PY
```

預期輸出：三行的比值都是 `0.385`。
